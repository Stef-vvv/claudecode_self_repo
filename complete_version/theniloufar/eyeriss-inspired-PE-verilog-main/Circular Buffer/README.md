# Circular FIFO Buffer Implementation — Eyeriss-Based Project

## Objective

Implement FIFO and circular buffer modules used in Eyeriss accelerator architecture. These buffers are responsible for handling intermediate data during execution, supporting parallel reads/writes, managing overflow/underflow conditions, and coordinating control handshakes.

## Architecture Overview

The system consists of several Verilog modules implementing:

- Basic FIFO buffer
- Circular FIFO buffer with overflow and empty detection
- Parameterized read/write parallelism
- Handshake signaling (`valid`, `ready`, `en_read`, `en_write`)
- Testbench to simulate and verify functionality

## Modules and Files

### `components.v`

Contains reusable components:

- Array-based memory for buffers
- Support for parameterized depth, width
- Multiplexers and demultiplexers for parallel access
- Counter modules for tracking read/write indices

### `controller.v`

Implements the control logic for:

- Managing valid and ready signals
- Generating full and empty conditions
- Handling resets, handshakes, and read/write enable

### `datapath.v`

Implements the data movement logic:

- Read and write address calculation
- Memory access interface
- Aggregation of parallel reads/writes
- Mapping of circular buffer address logic

### `toplevel.v`

Top-level module that connects:

- Components
- Controller
- Datapath
  Also provides an external interface to testbench.

### `testbench.sv`

SystemVerilog testbench:

- Simulates various scenarios
- Verifies read/write behaviors
- Checks correctness of full/empty detection
- Evaluates behavior under parallel data access

## Functional Requirements

### FIFO Buffer (Normal Buffer)

- Temporary storage for stream data
- Simultaneous read and write support
- Parameters:
  - `DEPTH`: default 8
  - `WIDTH`: adjustable
  - `READ_PAR`: 1/2/4
  - `WRITE_PAR`: 1/2/4

### Circular FIFO Buffer

- Implements ring-like memory behavior
- Uses two pointers:
  - `read_ptr`
  - `write_ptr`
- Circular increment with modulo operations
- Conditions:
  - `empty`: `read_ptr == write_ptr`
  - `full`: `write_ptr + WRITE_PAR == read_ptr`

## Handshake Protocol

### Write

- `en_write` is received externally
- `ready` is generated by buffer: only high if there is enough space for `WRITE_PAR`
- Data is written on `clk` rising edge

### Read

- `en_read` is activated when consumer is ready
- `valid` is generated internally: high when at least `READ_PAR` elements are available
- Data is read combinationally

## Design Notes

- Overflow protection: writes are rejected if space is insufficient
- Underflow protection: reads are rejected if data is unavailable
- Use `generate` and `for` loops to support arbitrary levels of parallelism
- Use clean Verilog-2001 syntax with parameters
- Fully test edge cases in `testbench.sv`: wrap-around, burst writes, empty reads

## Testing & Validation

Run simulation using ModelSim/VCS or your preferred tool. The testbench:

- Initializes buffer
- Applies burst writes and reads
- Tests circular behavior
- Verifies control signals

## Constraints & Assumptions

- Max buffer depth: 8
- Parallelism values allowed: 1, 2, 4
- Data is read combinationally; written on clock edge
- Overflow: entire write batch is rejected if not enough space
- Read and write can happen simultaneously
