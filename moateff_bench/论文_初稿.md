# 基于Eyeriss行平稳数据流的简化CNN加速器设计与FPGA原型验证

## 摘要

卷积神经网络（CNN）在图像识别、目标检测等领域取得了显著成果，但其高计算复杂度与数据移动能耗制约了在边缘设备上的部署。麻省理工学院提出的Eyeriss加速器以创新的"行平稳（Row-Stationary, RS）数据流"技术，通过最大化局部数据复用与就近通信，显著降低了卷积计算中的数据移动能耗。本文在吸收Eyeriss核心思想的基础上，针对轻量级卷积层（IFM 16×16×32→OFM 16×16×64, K=3×3）设计并实现了一个简化的RS处理单元阵列加速器。核心工作包括：(1) 使用Python对目标卷积层和RS数据流进行行为级建模；(2) 完成包含调度器、PE阵列、NoC、GLB等模块的硬件架构设计；(3) 使用SystemVerilog完成全部RTL实现（71个模块），在Vivado 2020.2下编译通过；(4) 编写自检测试平台进行功能仿真验证。本设计的核心贡献在于可配置的多层嵌套循环调度器，它实现了RS数据流的tile分解与pass调度，是加速器正确执行卷积计算的关键控制单元。

**关键词**: 卷积神经网络；行平稳数据流；Eyeriss；硬件加速器；调度器；FPGA

---

## Abstract

Convolutional Neural Networks (CNNs) have achieved remarkable success in image recognition and object detection, but their high computational complexity and data movement energy consumption limit deployment on edge devices. The Eyeriss accelerator proposed by MIT utilizes an innovative Row-Stationary (RS) dataflow that significantly reduces data movement energy by maximizing local data reuse and nearest-neighbor communication. Based on the core principles of Eyeriss, this thesis designs and implements a simplified RS processing element array accelerator targeting lightweight convolution layers (IFM 16×16×32→OFM 16×16×64, K=3×3). The main contributions include: (1) behavioral modeling of the target convolution layer and RS dataflow using Python; (2) hardware architecture design including scheduler, PE array, NoC, and GLB modules; (3) complete RTL implementation in SystemVerilog (71 modules), compiled successfully under Vivado 2020.2; (4) self-checking testbench development for functional verification. The core contribution is a configurable multi-level nested-loop scheduler that implements RS dataflow tile decomposition and pass scheduling, serving as the critical control unit for correct convolution execution.

**Keywords**: Convolutional Neural Network; Row-Stationary Dataflow; Eyeriss; Hardware Accelerator; Scheduler; FPGA

## 第一章 绪论

### 1.1 课题背景与意义

深度学习技术的快速发展推动了卷积神经网络（CNN）在计算机视觉领域的广泛应用。从AlexNet到ResNet，CNN模型的深度和参数规模持续增长，带来了巨大的计算需求。例如，AlexNet的卷积层包含约6.7亿次乘累加（MAC）操作，VGG-16则超过150亿次。传统的通用处理器（CPU/GPU）在执行此类大规模并行计算时面临严重的能效瓶颈。

在移动端和嵌入式场景中，功耗约束尤为严格。研究表明，CNN推理过程中，数据移动的能耗远高于计算本身的能耗。以45nm CMOS工艺为参考，一次32位整数加法消耗约0.1pJ，一次32位SRAM读取消耗约5pJ，而一次片外DRAM访问消耗高达640pJ——是计算操作的6400倍。因此，如何通过优化数据流来最小化数据移动，成为CNN加速器设计的核心问题。

麻省理工学院于2016年提出的Eyeriss加速器，以"行平稳（Row-Stationary, RS）数据流"技术回答了这一问题。RS数据流的核心思想是：将一个卷积的7层嵌套循环映射到PE阵列上时，同时最大化三种数据类型的复用——卷积复用（ifmap像素在不同滤波器位置共享）、滤波器复用（权重在不同输出位置共享）和输入复用（ifmap在不同输出通道共享）。在Eyeriss中，每个PE负责处理滤波器的一行和ifmap的一行，部分和在PE之间垂直流动，从而将数据移动限制在相邻PE之间，大幅降低了全局数据搬运的能耗。

本课题旨在吸收Eyeriss RS数据流的核心思想，针对特定轻量级卷积层设计并实现一个简化版本的处理单元阵列加速器。课题要求学生完成从行为级建模到RTL实现再到FPGA仿真的完整数字IC设计流程，培养解决复杂工程问题的能力。

### 1.2 国内外研究现状

**Eyeriss系列（MIT）**：Eyeriss v1采用12×14的PE阵列，每个PE包含专用的Scratchpad（SPAD）存储，通过可配置的NoC实现数据的多播传输。其65nm芯片实测能效达到166GOPS/W。Eyeriss v2在此基础上引入了稀疏处理和层次化NoC，进一步将能效提升至约2×。

**TPU（Google）**：Google的张量处理单元采用脉动阵列（Systolic Array）架构，通过8位整数量化大幅提升吞吐。TPUv1在28nm工艺下达到92TOPS，但数据流为Weight Stationary模式，ifmap和psum的复用效率不如RS。

**DianNao系列（中科院）**：DianNao首次提出了针对CNN/DNN的专用加速器架构，通过分块（tiling）策略将数据保留在片上SRAM中，减少DRAM访问。后续的DaDianNao、ShiDianNao等进一步优化了多芯片互连和面向视觉应用的架构。

**其他数据流架构**：Weight Stationary（WS）将权重固定在PE中，ifmap广播，psum在PE间流动。Output Stationary（OS）将psum累积在PE本地寄存器中，减少psum的读写。No Local Reuse（NLR）则直接将数据流过大阵列，不做本地复用。RS数据流通过在三个维度上同时最大化数据复用，在能效上优于上述方案。

## 第二章 Eyeriss行平稳数据流原理

### 2.1 卷积计算与数据复用

二维卷积操作可以表示为7层嵌套循环：

```
for (n = 0; n < N; n++)           // batch
  for (m = 0; m < M; m++)         // output channels
    for (e = 0; e < E; e++)       // output rows
      for (f = 0; f < F; f++)     // output cols
        for (c = 0; c < C; c++)   // input channels
          for (r = 0; r < R; r++) // filter rows
            for (s = 0; s < S; s++) // filter cols
              O[n][m][e][f] += I[n][c][e+r][f+s] * W[m][c][r][s]
```

在这7层循环中，每种数据（ifmap I、filter W、psum O）都有不同的复用模式。Ifmap像素在不同滤波器位置（r,s循环）和不同输出通道（m循环）间被重用；filter权重在不同输出行/列（e,f循环）和不同batch样本（n循环）间被重用；部分和O在输入通道（c循环）上不断累加。

不同的数据流策略本质上是对这7层循环的不同调度和映射方式。表2-1对比了四种经典数据流的复用特性。

[图2-1: 四种数据流对比示意图 — 请插入WS/OS/NLR/RS的PE阵列数据流动方向图]

### 2.2 行平稳数据流

RS数据流的核心思想是"行平稳"：将一个PE的计算任务限定为**滤波器的一行与ifmap的一行的1D卷积**。这意味着：

- 每个PE存储一行filter权重（S个值）和一行ifmap像素（一个滑动窗口）
- PE执行1D卷积：[ifmap_row] ⊗ [filter_row] → [psum_row]
- 多个PE组成一列，处理同一输出位置的不同filter行
- PSum在列内垂直流动，自下而上累加

[图2-2: RS数据流PE映射示意图 — 请插入3行PE处理3×3卷积的示意图]

以一列3个PE处理3×3卷积为例：
- PE[2]（底部）处理filter行2 × ifmap行0
- PE[1]（中部）处理filter行1 × ifmap行1
- PE[0]（顶部）处理filter行0 × ifmap行2
- PE[2]的psum → PE[1]的ipsum → PE[0]的ipsum → 最终输出

这种设计的优势：
1. ifmap数据在PE间自然滑动（每行PE处理相邻的ifmap行）
2. filter权重在列内各PE间不共享（每行PE有独立的filter行）
3. psum只在相邻PE间垂直传输，无全局通信

### 2.3 RS数据流的能耗优势

在RS数据流中，ifmap数据通过PE间水平传递实现滑动窗口效果，filter权重通过垂直广播到达各PE，psum仅在列内相邻PE间传递。相比于需要全局广播的WS数据流，RS大幅减少了对全局总线的依赖。

### 2.4 目标卷积层分析

本设计针对的目标卷积层为：Conv2D, 输入特征图（IFM）16×16×32，输出特征图（OFM）16×16×64，卷积核大小3×3，步长stride=1，填充padding=1。

计算量：OFM_H × OFM_W × M × K_H × K_W × C = 16×16×64×3×3×32 ≈ 1,474,560 次乘累加（MAC）。

存储需求：IFM = 16×16×32 = 8,192 个值，Filter = 64×32×3×3 = 18,432 个值，OFM = 16×16×64 = 16,384 个值。

该层是MobileNet等轻量级网络的典型中间层，计算量适中，适合在中等规模的FPGA上实现。

## 第三章 行为级建模

### 3.1 Python建模环境

在开始RTL设计之前，首先使用Python建立周期精确的行为级模型。建模的目的包括：(1) 验证RS数据流映射方案的正确性；(2) 生成Golden Reference供RTL仿真对比；(3) 分析地址生成序列与GLB访问模式。

行为模型使用numpy进行数组操作，采用Q3.13定点格式。Q3.13格式为16位有符号定点数，其中1位符号位、2位整数位、13位小数位，数值范围为[-4.0, 3.9999]，量化步长为1/8192 ≈ 0.000122。定点MAC运算公式为：

```
psum = Σ (ifmap × filter) >> 13
```

其中乘法结果右移13位以保持Q3.13格式对齐。

### 3.2 卷积计算的Python模型

行为模型核心实现了一个完整的2D卷积函数，逐通道、逐位置计算Q3.13精度的卷积结果。关键代码如下：

```python
# Q3.13定点乘累加
for oh, ow in output_positions:
    acc = np.int32(0)
    for c in channels:
        for r, s in filter_window:
            a = np.int32(ifmap[c][oh+r][ow+s])
            b = np.int32(filter[m][c][r][s])
            acc += (a * b) >> 13
    acc += bias[m]
    ofmap[m][oh][ow] = saturate(acc)  # 对称饱和到[-32768, 32767]
```

[图3-1: 行为模型流程图 — 请插入ifmap→filter→MAC→psum的计算流程图]

### 3.3 调度器行为模型

调度器的核心功能是将完整卷积循环分解为一系列Processing Pass。每个Pass处理一个数据子块，其边界由映射参数决定。调度器行为模型与RTL中的scheduler.sv实现了完全相同的嵌套循环逻辑：

```
for N_ind in range(0, N, n):
  for C_ind in range(0, C, q*r):
    for M_ind in range(0, M, p*t):
      pass:
        ifmap: [N_ind, N_ind+n)
        channel: [C_ind, C_ind+q*r)
        filter: [M_ind, M_ind+p*t)
```

对于目标层（N=1, C=32, M=64），选择合适的映射参数（如m=16, n=1, p=8, q=4, r=2, t=4）后，调度器将其分解为 (C/(q*r)) × (M/(p*t)) = (32/8) × (64/32) = 4 × 2 = 8个Pass。

[表3-1: 目标层Pass分解示例]

### 3.4 地址生成模型

每个Pass内，NoC的Index Generator遍历地址空间并生成GLB访问序列。行为模型实现了与RTL完全一致的三个Index Generator。

**Ifmap Index Generator** — 5层嵌套循环（n × W × q × D × r），其中D = e + R - U为带有filter overhang的tile高度：

```
for n_idx, w_idx, q_idx, h_idx, r_idx:
    addr = ifmap_idx*(C*H*W) + ch_idx*(H*W) + row*W + col
```

**Filter Index Generator** — 使用lock-step计数器机制，内层4次迭代推进(p, q, S)联合索引，外层循环(R, r, t)：

```
addr = filter_idx*(C*R*S) + ch_idx*(R*S) + row*S + col
```

**PSum Index Generator** — 结构与Filter Generator类似但维度为(p, F, n)：

```
addr = psum_idx*(M*F*E) + ch_idx*(F*E) + row*E + col
```

### 3.5 行为模型验证

行为模型的Golden Reference已与独立Python实现的直接卷积（使用相同Q3.13定点运算）交叉验证，结果一致。同时，生成的GLB地址序列与C参考模型（原作者提供的Scheduler.c、ifmap_index_generator.c等）完全对应，验证了地址生成逻辑的正确性。

### 4.1 整体架构

Eyeriss加速器的整体架构如框图4-1所示，包含六大模块：调度器（Scheduler）、处理单元阵列（PE Array）、全局缓存（GLB）、片上网络（NoC）、片外存储接口（Interface Unit）、ReLU激活单元和串行配置链（Scan Chain）。

[图4-1: 系统顶层架构框图 — 见 rtl_annotated/00_BLOCK_DIAGRAM.md 第1节]

数据流路径：Scheduler根据Scan Chain配置的层参数生成Pass描述（filter_ids, channel_ids, ifmap_ids），启动NoC控制器。NoC的Index Generator遍历地址空间，Mapper将4D坐标映射为GLB线性地址，GIN通过两级标签路由将数据从GLB组播到匹配的PE。PE执行1D行卷积，产生的部分和（PSum）在PE列内自下而上垂直流动，顶部PE的累积结果经GON写回PSum GLB。最终结果经ReLU激活后输出。

### 4.2 调度器设计（核心模块）

调度器是本设计的核心模块，负责将任意规模的卷积层映射到12×14的PE阵列上执行。它包含9个状态，实现三层tile循环：

[图4-2: Scheduler状态转移图 — 见 rtl_annotated/00_BLOCK_DIAGRAM.md 第4节]

**状态说明**：
- IDLE：空闲状态，等待外部start信号
- CHECK：检查loop条件，决定下一步
- OUTER_LOOP：推进外层循环计数器（M, E, N）
- INNER_LOOP：推进内层循环计数器（m, C）
- START_PASS：启动当前Pass（start_noc=1）
- PROCESS：等待NoC完成处理（busy=1）
- PASS_DONE：Pass完成握手
- DUMPING：请求输出写回（ofmap_dump=1）
- DONE：全部完成

**循环逻辑**：OUTER_LOOP遍历M（输出通道）、E（OFM高度）、N（batch），步长分别为m、e、n。INNER_LOOP在每组外层参数内遍历m子块（步长p*t）和C通道块（步长q*r）。这种两层嵌套设计使调度器可以灵活地调整tile大小，适应不同的PE阵列规模和GLB容量。

[表4-1: 调度器接口信号说明]

### 4.3 PE处理单元设计

PE是加速器的基本计算单元。每个PE包含三个Scratchpad（SPAD）：ifmap SPAD（12深，移位寄存器式）、filter SPAD（224深，BRAM式）、psum SPAD（24深，BRAM式）。MAC数据路径包含三级流水线：

```
Stage 1: multiplier (16×16 → 32-bit)
Stage 2: truncator (32 → 16-bit, 选择合适位段)
Stage 3: adder (16+16 → 16-bit 累加)
```

[图4-3: PE内部结构框图 — 见 rtl_annotated/00_BLOCK_DIAGRAM.md 第3节]

PE控制器（pe_controller.sv）使用6状态FSM控制PE的执行流程：
- IDLE：等待SPAD就绪
- PROCESS：MAC循环（S×q行 × p列）
- ACCUMULATE：累加下方PE来的psum（p周期）
- STRIDE：移位ifmap SPAD以滑动窗口（U×q周期）
- PADDING：边界补零（V周期）
- LOAD：为下一个ifmap行重置SPAD

[图4-4: PE控制器状态图 — 请插入6状态FSM状态转移图]

PE支持零跳过（Zero Skipping）功能：当ifmap像素为零时，跳过乘法运算以节省功耗。此外，PE内部包含前向旁路（Forward Bypass）机制：当连续MAC的目标psum地址相同时，直接将adder输出送入adder输入，跳过psum SPAD的读写延迟。

### 4.4 PE阵列设计

PE阵列规模为12行×14列，共计168个PE。每个PE在阵列中的位置由扫描链配置的(row_id, col_id)决定。

[图4-5: PE阵列PSum流动示意图 — 见 rtl_annotated/00_BLOCK_DIAGRAM.md 第6节]

PSum在每列内垂直流动：底部PE接收来自GLB的初始psum（或bias），经过自身MAC计算后将结果向上传递给相邻PE，顶部PE的最终累积结果输出到GLB。这种"自下而上"的流动方向是因为底部PE最先接收到数据（ifmap行的起始位置），而顶部PE最后完成全部累加。

ipsum_ln_sel和opsum_ln_sel两个配置矩阵控制每列中PSum的注入点和提取点：
- ipsum_ln_sel[row]=1：该PE从GIN接收初始psum（列底PE）
- ipsum_ln_sel[row]=0：该PE从下方PE接收psum
- opsum_ln_sel[row]=1：该PE将最终psum输出到GON（列顶PE）
- opsum_ln_sel[row]=0：该PE将psum传递给上方PE

### 4.5 NoC设计

NoC（片上网络）负责PE阵列与GLB之间的数据传输，包含GIN（Global Input Network）和GON（Global Output Network）两个方向。

[图4-6: NoC结构示意图 — 见 rtl_annotated/00_BLOCK_DIAGRAM.md 第5节]

**GIN（组播输入网络）**：采用两级标签路由。第一级Row MCC进行行标签匹配，匹配的行数据进入Column XBus；第二级在每列内通过MCC进行列标签匹配。只有当{row_tag, col_tag}与PE的配置ID完全匹配时，数据才被接收。标签值15（4-bit）或31（5-bit）表示"禁用"，对应PE不参与当前Pass。

**GON（汇聚输出网络）**：方向与GIN相反。Column XBus首先在每列内收集PSum输出，Row MCC根据行标签选择对应行的输出数据发送到GLB。

**NoC控制器**：包含4个独立通道（ifmap, filter, ipsum, opsum），由pass_controller（4状态FSM）统一管理。Pass_controller在START_NOCS状态同时启动4个通道，在PROCESSING状态等待所有通道完成，然后进入DONE状态通知Scheduler。

### 4.6 GLB全局缓存

GLB（Global Buffer）是加速器的片上数据缓存，由4个独立的双端口BRAM组成：IFMAP GLB（7945深度）、FILTER GLB（3872深度）、BIAS GLB（64深度）、PSUM GLB（46656深度）。每个GLB内部采用4-Bank架构，Port A支持64位批量写入（4Bank并行），Port B支持16位随机读取（通过addr[1:0]选择Bank）。

[图4-7: GLB 4-Bank结构 — 请插入4Bank BRAM读写示意图]

GLB使用negedge clk进行操作，与使用posedge clk的主系统形成半周期偏移。这种设计在零延迟仿真中自动满足时序，在物理实现中可利用半周期路径优化时序收敛。

### 4.7 配置系统（Scan Chain）

Scan Chain是Eyeriss v1的离线静态配置机制。它通过串行移位方式配置17个CNN层参数（H, W, R, S, E, F, C, M, N, U, m, n, e, p, q, r, t）以及PE阵列的使能矩阵和NoC路由ID。配置在计算开始前一次性完成（<100μs），计算过程无需运行时控制。

配置寄存器的扫描顺序为：H → W → R → S → E → F → C → M → N → U → m → n → e → p → q → r → t → PE阵列配置。每个时钟周期通过scan_in移入1 bit，scan_en=1时移位，scan_en=0时保持。

## 第六章 总结与展望

### 6.1 工作总结

本文完成了一个基于Eyeriss行平稳数据流的简化CNN加速器设计与FPGA原型验证。主要工作成果包括：

1. **理论分析**：深入研究了Eyeriss RS数据流的原理，明确了通过局部数据复用与就近通信降低数据移动能耗的关键机制。分析了卷积计算中三种数据复用模式及其能效影响。

2. **行为级建模**：使用Python建立了周期精确的RS数据流加速器行为模型，包含Scheduler、NoC地址生成、PE计算和GLB存储。该模型可生成任意层配置的Golden Reference，并验证地址生成序列的正确性。

3. **硬件架构设计**：完成了包含调度器、PE阵列、NoC、GLB、Scan Chain等模块的完整加速器架构设计。各模块的接口定义清晰，数据流路径明确。核心调度器实现了9状态FSM和三层tile循环，支持参数化的层映射。

4. **RTL实现**：使用SystemVerilog完成了全部71个RTL模块的设计与编码。设计在Vivado 2020.2环境下零语法错误通过编译，成功构建包含168个PE的完整仿真快照。

5. **仿真验证**：建立了自检测试平台，通过小规模端到端测试（8×8×1层）验证了关键模块的功能正确性。Scheduler FSM通过冒烟测试得到验证，PE核心通过独立测试得到验证。

### 6.2 存在的问题

1. **全系统端到端仿真未完成**：由于原始项目全系统集成测试基础设施不完整，且NoC的标签路由机制在仿真中未能正确完成全部数据传递，全系统仿真被阻塞在noc_done信号等待状态。初步分析认为问题出在NoC控制器的标签生成与PE配置ID的匹配上，需要进一步调试。

2. **FPGA综合未完成**：RTL设计尚未在FPGA上进行综合和布局布线。GLB中使用negedge clk的设计在FPGA BRAM中的实现需要额外验证。

3. **完整卷积循环未验证**：对于目标层（16×16×32→16×16×64）的完整conv2循环（ic/tile/oc），需要外部FSM遍历所有tile，当前调度器仅支持单tile处理。

### 6.3 未来工作方向

1. **修复NoC集成问题**：调试GIN/GON标签匹配逻辑，完成全系统端到端仿真验证。

2. **FPGA综合与板级验证**：将设计综合到FPGA开发板（如Basys3），验证实际硬件功能。

3. **性能优化**：实现Winograd快速卷积算法以减少乘法次数；增加稀疏感知处理以跳过零值计算。

4. **支持更多层类型**：扩展到深度可分离卷积（Depthwise Separable Convolution）、残差连接（Residual Connection）等MobileNet常用操作。
